# 墨库 InkVault · 设计文档

> 版本 1.0.0 · 一份把「数据属于自己」放在第一位的个人知识库设计
>
> 目标不是做一个功能更多的笔记软件，而是做一个**十年后还能打开、还能迁走、还能信任**的笔记系统。

---

## 1. 设计目标与原则

### 1.1 五条不可妥协的原则

| 原则 | 具体含义 | 落在实现上 |
| --- | --- | --- |
| **本地优先** | 默认不依赖任何云服务，断网可用 | SQLite 单文件 + 附件目录；服务端只监听本机/局域网 |
| **数据可迁移** | 任何时刻都能完整导出，不被格式锁定 | Markdown 为第一公民；六种目录格式；整库 ZIP + JSON |
| **最大兼容** | 能读别家的历史笔记，也能被别家读 | ENEX / HTML / Markdown / JEX / Notion / CSV / JSON 导入；标准 Markdown 导出 |
| **可容纳** | 十万级笔记仍然可检索、可整理，不因规模崩坏 | WAL、分页、索引、FTS5、附件流式读取、按需加载 |
| **可理解** | 结构清晰，用户知道数据在哪、发生了什么 | 目录树 + 标签 + 自定义字段；备份可见；访问日志可查 |

### 1.2 明确不做的事

- **不做云端账号体系**：没有注册、没有订阅、没有「同步到我们的服务器」。
- **不做私有二进制格式**：数据库是标准 SQLite，笔记是 Markdown，导出是 ZIP。
- **不做花哨但不可逆的 AI 加工**：所有自动生成的内容（目录、统计）都以普通笔记/普通文件落地，可修改、可删除。

```
│  │ 路由/鉴权 │ │ 7 类导入  │ │ 目录/报告 │ │ SQLite │ │ 内嵌 web   │  │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └───┬────┘ └───────────┘  │

                ┌─────────▼─────────┐
                │  vault/            │
                │   vault.db  (WAL)  │
                │   files/   附件     │
                │   backups/ 备份     │
                │   config.json      │
                └───────────────────┘
```

### 3.1 为什么是「单二进制 + 内嵌前端」

1. **部署为零**：一个文件就是整个应用，没有 Node、没有 Python、没有数据库服务。
2. **数据路径可控**：数据库永远在进程旁边（或 `~/InkVault`），不会跑到系统深处。
3. **离线可用**：前端资源编译进二进制，断网也能打开。
4. **跨平台一致**：Go 交叉编译出 macOS/Windows/Linux 三份产物，行为完全一致。
5. **易迁移**：换电脑时复制 `vault/` 目录即可，不需要「导出/导入」也能搬走。

### 3.2 请求链路

```
浏览器 → 静态资源（内嵌） → 前端 app.js
       → /api/*（PIN 会话或 API Token）
       → store（SQLite） → 返回 JSON
       → 导出请求直接返回文件流（Content-Disposition）
```

## 4. 数据模型

### 4.1 表结构总览

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `notes` | 笔记主表 | `uid`、`title`、`content`、`excerpt`、`notebook_uid`、`status`、`pinned/starred`、`word_count`、`created_at`、`updated_at`、`deleted_at` |
| `notebooks` | 笔记本树 | `uid`、`name`、`parent_uid`、`sort`、`color` |
| `tags` / `note_tags` | 标签与多对多 | `uid`、`name`、`color` |
| `attachments` | 附件元数据 | `uid`、`note_uid`、`filename`、`stored_name`、`mime`、`size` |
| `note_versions` | 历史版本 | `note_uid`、`title`、`content`、`reason`、`created_at` |
| `fields` / `field_values` | 自定义字段 | `type`、`options`、`scope`（全局或指定笔记本） |
| `templates` | 笔记模板 | `name`、`content`、`notebook_uid` |
| `saved_searches` | 保存的搜索 | `name`、`query` |
| `import_batches` | 导入记录 | `filename`、`format`、`created/updated/failed` |
| `audit_log` | 访问与写操作日志 | `action`、`target`、`ip`、`created_at` |
| `settings` | 键值设置 | 主题、默认笔记本、字段等 |
| `notes_fts` | 全文索引（FTS5 trigram） | `uid`、`title`、`content` |

### 4.2 关键设计决策

**① 一切用 `uid`（短字符串）而不是自增主键做业务引用**

同步、导入、导出、跨设备合并都需要稳定标识。自增 ID 在不同设备上会冲突，`uid` 用 9 字节随机数的十六进制（如 `nt-b205d8e8cf931dbd17`），跨库、跨设备唯一。

**② 时间戳统一为 UTC RFC3339 毫秒字符串**

`2026-11-16T19:27:20.865Z`，字典序即时间序，方便 SQL 比较与同步合并，也避免时区歧义。展示时再转本地时区。

**③ 软删除 + 回收站**

`deleted_at` 非空即进入回收站。同步时删除也会作为「墓碑」传播；永久删除才真正清理附件与版本。

**④ 版本历史是快照，不是 diff**

每次内容变化存一份全文，最多保留 40 份/篇。对个人笔记（KB 级）来说，快照实现简单、恢复可靠，比 diff 更不容易出错。

**⑤ 摘要是派生字段，可重建**

`excerpt` 与 `word_count` 由正文计算，启动时会自动回填修正。它们只服务于列表和目录，不参与事实来源。

**⑥ 附件与数据库分离**

数据库只存元数据，文件落在 `files/YYYY-MM/<uid>.<ext>`。备份时分别打包，恢复时一起还原；数据库因此保持小而快。

### 4.3 关系图

```
notebooks 1 ──< notes >── 1 notes_fts
                 │  │
                 │  └──< attachments
                 │  └──< note_versions
                 └──< note_tags >── tags
                 └──< field_values >── fields

templates ──(可选)──> notebooks
saved_searches（独立）
```

## 5. 检索系统

### 5.1 三层检索

| 层 | 触发 | 实现 | 延迟目标 |
| --- | --- | --- | --- |
| 即时过滤 | 列表内输入 | 前端高亮 + 服务端 LIKE（短词） | < 30 ms |
| 全文检索 | ≥ 3 个字符 | SQLite FTS5 `trigram` 索引 | < 80 ms / 万篇 |
| 结构化检索 | 搜索语法 | SQL 条件组合（tag/notebook/时间/星标） | < 50 ms |

### 5.2 为什么用 trigram 分词

中文没有空格，`unicode61` 会把整句当成一个词，召回极差。`trigram` 把文本切成三字符片段，天然支持中文子串检索，也能兼顾英文单词片段。两字词（如「架构」）不足三个字符，FTS 无法命中，因此自动降级为 `LIKE '%架构%'`。

> 实现细节：`store.Notes()` 先解析搜索语法，再判断每个词的长度；全部 ≥ 3 字符才走 FTS，否则逐词 LIKE 并用 AND 连接。这样既保证中文短词可用，也避免全部退化。

### 5.3 搜索语法

| 语法 | 含义 | 示例 |
| --- | --- | --- |
| `关键词` | 标题 + 正文，多词 AND | `架构 演化` |
| `tag:名称` / `#名称` | 按标签 | `tag:方法论` |
| `notebook:名称` | 按笔记本 | `notebook:工作` |
| `is:starred` | 星标 | `is:starred` |
| `is:pinned` | 置顶 | `is:pinned` |
| `is:trashed` | 回收站 | `is:trashed` |
| `before:2026-01-01` | 更新时间早于 | `before:2026-01-01 复盘` |
| `after:2026-01-01` | 更新时间晚于 | `after:2026-01-01` |

### 5.4 排序

- 有搜索词时默认**相关度**：标题命中权重 ×4，正文按出现次数累计；置顶优先。
- 无搜索词时默认**最近更新**；可切换最近创建、标题、字数、最早更新。
- 列表分页 60 条，滚动按需加载，避免一次渲染上千条 DOM。

### 5.5 结果呈现

- 标题与摘要命中词高亮；
- 摘要由正文提取（跳过标题、代码块、表格），保证可读；
- 命令面板（⌘K）同时搜索标题与正文，回车直接打开；
- 搜索结果可「保存为搜索」，固定出现在侧栏。

## 6. 组织与分类

### 6.1 笔记本：无限层级

- `parent_uid` 自引用，支持任意深度；侧栏用缩进 + 折叠展示。
- 删除笔记本不会删笔记：笔记与子笔记本上移到父级，避免误操作造成数据丢失。
- 每个笔记本可设置颜色、图标、描述（数据层已支持，界面逐步开放）。

### 6.2 标签：扁平、多对多

- 标签不设层级，降低心智负担；用 `#项目/子项` 这样的命名可以模拟层级。
- 标签随笔记自动出现，无笔记的标签自动隐藏。
- 右键标签可重命名、删除（删除只解除关联，不删笔记）。

### 6.3 自定义字段：给笔记加「列」

字段定义（`fields`）支持：

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| text | 普通文本 | 作者、出版社 |
| number | 数字 | 评分、页码 |
| date | 日期 | 读完日期 |
| select | 单选 | 阅读状态：未读/在读/已读 |
| multiselect | 多选 | 主题：产品/技术/管理 |
| checkbox | 勾选 | 已归档到纸质本 |
| url | 链接 | 原文地址 |

字段可以限定作用域（全局或某个笔记本）。在编辑器中以一行属性条呈现，不干扰正文。

### 6.4 模板：把重复结构固化

- 模板就是一段 Markdown，保存后在命令面板（⌘K）里以「模板：周报」形式出现。
- 选择模板 → 新建笔记 → 自动填入结构，标题可改。
- 适合：周报、会议记录、读书笔记、面试记录、旅行清单。

### 6.5 自动目录笔记

「生成目录笔记」会把某个笔记本（含子笔记本）下的所有笔记汇总成一篇普通笔记：

```markdown
# 目录 · 技术

> 自动汇总 · 共 42 篇 · 更新于 2026-11-17

- [索引与检索设计](#/note/nt-xxx) · 1,204 字 · #检索 #SQLite
- [Go 并发模型](#/note/nt-yyy) · 860 字 · #Go
```

它的价值在于：目录本身也是笔记，可以被搜索、被链接、被再次整理，而不是一个只读的界面。

## 7. 目录与报告引擎

这是本产品最核心的「输出能力」，也是与普通笔记软件拉开差距的地方。

### 7.1 目录文档（TOC）

**输入**：当前筛选范围（全部 / 笔记本 / 标签 / 搜索结果 / 星标）、排序方式。

**可配置项**：

| 选项 | 取值 | 说明 |
| --- | --- | --- |
| 格式 | Markdown / HTML / CSV / XLSX / DOCX / JSON | 对应不同使用场景 |
| 分组 | 按笔记本 / 按标签 / 按月份 / 不分组 | 只影响排版，不丢信息 |
| 简介长度 | 一句话 / 适中 / 详细 / 不显示 | 60 / 110 / 180 字 |
| 包含标签 | 是 / 否 | |
| 包含时间 | 是 / 否 | |
| 包含字数 | 是 / 否 | |
| 连续编号 | 是 / 否 | 跨分组统一编号 |

**输出示例（Markdown）**：

```markdown
# 知识库目录

> 生成于 2026-11-17 03:41 · 共 15 篇 · 707 字 · 我的知识库

## 分组概览

- **工作** — 3 篇 · 176 字
- **生活** — 3 篇 · 76 字

## 工作

1. [架构设计的三条原则](#/note/nt-xxx)
   好的架构不是设计出来的，是演化出来的。先划清模块边界…
   *#方法论 #架构 · 100 字 · 更新于 2026-11-16*
```

**格式选择建议**：

| 场景 | 推荐格式 | 原因 |
| --- | --- | --- |
| 放进 Obsidian / 博客 | Markdown | 通用、可继续编辑 |
| 打印 / 发给别人 | HTML 或 DOCX | 排版稳定、可点击 |
| 筛选、排序、二次统计 | XLSX | 支持列筛选与透视 |
| 数据交换 / 脚本处理 | JSON | 完整结构 |
| 快速导入表格软件 | CSV | 最轻量 |

**HTML 版本的设计**：A4 阅读版式、封面信息、分组导航、条目卡片、打印样式；每条可点击回应用内对应笔记（使用当前服务地址生成链接）。即使脱离应用，也是一份可读的文档。

### 7.2 统计报告

统计分三层，满足「看」与「留」两种需求：

1. **实时仪表盘**：KPI、月度趋势、记录热度、笔记本/标签分布、最长笔记。
2. **统计快照笔记**：一键写入知识库，成为一篇普通笔记（`数据概览 · 2026-11`），可搜索、可回顾。
3. **统计报告文件**：HTML（带图表、可打印）、XLSX（6 个工作表）、DOCX、CSV、Markdown。

指标定义：

| 指标 | 定义 |
| --- | --- |
| 笔记数 | 未删除且未归档 |
| 总字数 | 中文按字、英文按词累计 |
| 篇均字数 | 总字数 / 笔记数 |
| 连续记录 | 从今天（或昨天）向前连续有编辑的天数 |
| 记录热度 | 近 365 天每日编辑次数 |
| 月度趋势 | 近 18 个月新增与字数 |
| 最活跃 | 编辑次数最多的星期 |

### 7.3 整库导出

```
我的知识库/
├── 目录.md
├── 目录.html
├── 工作/
│   ├── 架构设计的三条原则.md
│   └── 本周复盘.md
├── 技术/
│   └── Go 语言/
│       └── Go 并发模型笔记.md
├── _附件/
│   └── at-xxxx.png
├── 数据.json
├── 全部笔记.enex（可选）
└── manifest.json
```

- 目录结构 = 笔记本结构，可直接拖进 Obsidian / Logseq。
- 每篇 Markdown 带 YAML 头（标题、标签、笔记本、创建/更新时间、uid）。
- 图片链接改写为相对路径，保证离线可读。
- `manifest.json` 记录数量、时间、版本，便于校验。

## 8. 导入系统

### 8.1 格式矩阵

| 来源 | 支持格式 | 处理方式 | 保留内容 |
| --- | --- | --- | --- |
| 印象笔记 / Evernote | `.enex` | 解析 XML，HTML→Markdown | 标题、正文、标签、附件、创建/更新时间、来源链接 |
| 锤子便签 | Markdown（ZIP 或单文件） | 文件夹→笔记本，图片→附件 | 标题、正文、分类、时间 |
| Apple 备忘录 | HTML 文件夹 / ZIP | 解析 HTML，图片→附件 | 标题、正文、图片 |
| 有道云笔记 / 为知笔记 | HTML / Markdown | 通用 HTML 解析 | 正文、图片 |
| Obsidian / Logseq | 文件夹 ZIP | 保留层级，frontmatter 标签、双链 | 层级、标签、附件 |
| Notion | 导出 ZIP（Markdown + CSV） | 页面→笔记，子页面→笔记本，CSV→表格笔记 | 层级、正文、附件 |
| Joplin | `.jex`（tar） | 解包 Markdown 与 resources | 正文、附件 |
| 通用 | CSV / TSV / JSON / TXT | 列名智能映射 | 标题、正文、标签、笔记本、时间 |

### 8.2 导入流水线

```
上传文件 → 识别格式（扩展名 + 内容嗅探）
        → 解包（ZIP/TAR/GZIP）
        → 解析为统一的 IncomingNote 结构
        → 附件二进制挂载为占位符 {{INKATT:n}}
        → 创建笔记 → 保存附件 → 回填 /api/files/<uid>
        → 笔记本路径自动创建（A / B / C）
        → 记录 import_batches
```

### 8.3 细节处理

- **编码**：UTF-8 优先；非法 UTF-8 自动用 GB18030 解码，兼容老 Windows 导出。
- **HTML**：自研 DOM 遍历转 Markdown，支持标题、列表、引用、代码块、表格、图片、任务列表；未知标签降级为文本而不是丢弃。
- **附件**：ENEX 的 `<en-media hash>` 按 MD5 匹配资源；Markdown 的相对路径按「笔记目录 → 根目录 → 文件名」三级查找。
- **Notion 文件名**：自动去掉末尾 32 位哈希。
- **双链**：`[[笔记]]` 转为普通文本，`![[图片]]` 转为附件引用。
- **安全**：解包拒绝 `..` 路径；单文件上限 128 MB，压缩包上限 512 MB。

### 8.4 导入原则

> **只增不改。** 导入永远创建新笔记，不覆盖现有内容；即使重复导入，也只会多出副本，不会破坏已有数据。

## 9. 导出系统

### 9.1 单篇导出

| 格式 | 适用 |
| --- | --- |
| Markdown | 继续编辑、放入其他工具 |
| HTML | 自包含图片（base64），可直接分享 |
| DOCX | 正式文档、打印 |
| TXT | 纯文本归档 |
| JSON | 结构化处理 |
| ENEX | 迁回印象笔记 |

### 9.2 技术实现

- **DOCX / XLSX 不依赖第三方库**：直接生成 OOXML（zip + XML），避免引入庞大依赖，也避免许可证问题。
- **HTML 导出**：Markdown→HTML 渲染器（Go 版）+ 内联样式 + 图片 base64。
- **ENEX 导出**：Markdown→HTML→`en-note`，附件按 MD5 生成 `<en-media>`，保证印象笔记可识别。

### 9.3 命名与编码

- 文件名使用笔记标题，非法字符替换为 `-`，长度截断 60 字。
- CSV 带 UTF-8 BOM，Excel 打开不乱码。
- 下载响应使用 RFC 5987 `filename*=UTF-8''`，中文文件名在各大浏览器正常。

## 10. 备份与恢复

### 10.1 备份内容

```
inkvault-20261117-035218-manual.zip
├── vault.db          # VACUUM INTO 的一致性快照
├── files/            # 全部附件
├── manifest.json     # 版本、数量、主机、时间
└── 说明.txt
```

### 10.2 为什么用 `VACUUM INTO`

直接复制 `.db` 文件在 WAL 模式下可能拿到不一致状态。`VACUUM INTO` 由 SQLite 生成一个完整、紧凑、事务一致的副本，不需要停服。

### 10.3 恢复流程

```
选择备份 → 校验 zip 路径安全
        → 解压到暂存目录
        → 以只读方式打开，验证 notes 表可读
        → 自动创建「恢复前备份」
        → 关闭当前数据库
        → 旧库与附件改名为 .pre-restore-<时间>
        → 新库与附件就位
        → 重新打开数据库，刷新页面
```

任何一步失败都不会破坏现有数据；最坏情况是保留旧库并报错。

### 10.4 自动备份

- 默认每 24 小时检查一次，超过间隔则自动备份；
- 保留最近 14 份，自动清理更早的；
- 备份目录 `vault/backups/`，可直接复制到移动硬盘或网盘。

### 10.5 三层数据安全

1. **自动备份**：防误删、防升级失败。
2. **整库导出**：防软件不可用（Markdown + JSON 可被任何工具读）。
3. **手动冷备**：把 `vault/` 目录复制到另一块磁盘（推荐每月一次）。

## 11. 多端与同步

### 11.1 桌面端

- 服务端监听 `0.0.0.0:8790`，同机浏览器、局域网设备、花生壳公网均可访问。
- 桌面启动时自动打开 `http://127.0.0.1:8790/?pin=xxxx`，免去手动登录。

### 11.2 移动端离线模式

Android / iOS 外壳内嵌同一套前端资源，通过 `file://` 加载，数据存入 WebView 的 IndexedDB（不可用时降级 localStorage）。

离线模式能力：

- 笔记增删改查、笔记本、标签
- Markdown 编辑与预览
- 搜索、统计
- 目录导出（Markdown / HTML / CSV / JSON）
- 单篇导出（Markdown / HTML / TXT / JSON）
- 本地快照备份
- 与桌面端双向同步

### 11.3 同步协议

采用**全量快照 + 逐篇最后写入者胜（LWW）**：

```
手机                          服务端
  │  POST /api/login {pin}      │
  │ ──────────────────────────> │  返回 token
  │  GET /api/sync/pull         │
  │ ──────────────────────────> │  返回全部笔记（含墓碑）
  │  合并：updatedAt 较新者胜     │
  │  POST /api/sync/push        │
  │ ──────────────────────────> │  服务端再次按 updatedAt 合并
```

选择理由：

- 个人笔记量级（几千到几万）下，全量快照的代价可接受；
- 不需要维护复杂的增量游标与冲突队列；
- 任何一端重装后都能从对方恢复完整数据；
- 冲突策略简单可解释：**同一篇笔记，修改时间更晚的版本获胜**。

已知边界：

- 附件不参与移动端同步（体积大，且手机端不产生附件为主）；
- 两端同时修改同一篇笔记时，较早的修改会被覆盖（有版本历史可找回）。

## 12. 安全与外网访问

### 12.1 认证

| 机制 | 说明 |
| --- | --- |
| 访问码（PIN） | 默认 6 位随机数字，可在设置中修改；至少 4 位 |
| 会话 Cookie | `HMAC-SHA256(PIN派生密钥, 过期时间)`，HttpOnly、SameSite=Lax，默认 180 天 |
| API Token | 24 字节随机十六进制，App 与脚本通过 `X-Ink-Token` 调用 |
| 登录限流 | 同一 IP 连续失败 8 次，锁定 10 分钟 |
| 访问日志 | 记录登录成功/失败、导入、导出、同步、设置变更 |

### 12.2 花生壳 / 反向代理

服务端已为公网访问做了这些准备：

- 监听 `0.0.0.0`，不绑定 localhost；
- 识别 `X-Forwarded-Proto` / `X-Forwarded-Host`，生成正确的分享链接与二维码；
- 可配置「公网地址」，用于目录导出里的回链、同步说明、二维码；
- 可选「强制 HTTPS Cookie」，在 HTTPS 隧道下避免会话明文传输；
- `/api/sync/*` 与 `/api/login` 支持跨域（仅 token 鉴权，不允许跨域携带 Cookie）；
- 所有导出均为服务端生成的文件流，不依赖第三方 CDN。

**推荐配置**：

1. 花生壳映射类型选 **HTTPS**（若套餐支持），否则选 TCP；
2. 在「设置 → 公网地址」填入分配到的域名；
3. 访问码改为 8 位以上，不要使用生日/手机号；
4. 不需要外网时，在花生壳控制台暂停映射；
5. 定期查看「设置 → 访问日志」，发现异常登录立即改 PIN 与 Token。

### 12.3 威胁模型与边界

| 风险 | 缓解 |
| --- | --- |
| 公网被扫描、暴力破解 | PIN + 限流 + 日志；建议 HTTPS |
| 局域网内他人访问 | 默认要求登录；可关闭（不推荐） |
| 设备丢失 | 数据库未加密，建议开启 FileVault / BitLocker |
| 恶意网页跨域调用 | CORS 仅开放 ping/login/sync，且 sync 必须带 Token；Cookie 不允许跨域 |
| 备份泄露 | 备份是普通 zip，建议放在加密磁盘或加密压缩包中 |

> 本产品**不做端到端加密**：它假设你信任自己的电脑。若需要更高安全级别，请把 `vault/` 放在加密卷中。

## 13. 可容纳性与性能

### 13.1 容量估算

| 数据 | 规模 | 占用 |
| --- | --- | --- |
| 10,000 篇笔记（平均 1,000 字） | 约 1,000 万字 | 数据库约 40–60 MB |
| 100,000 篇笔记 | 约 1 亿字 | 数据库约 400–600 MB |
| FTS5 trigram 索引 | 约为正文的 1.2–1.6 倍 | 500–900 MB |
| 附件 | 取决于使用 | 视频/大图为主要占用 |

SQLite 单库支持 TB 级，瓶颈通常在附件而非笔记文本。

### 13.2 性能设计

- **WAL 模式**：读写并发不互相阻塞；
- **分页**：列表默认 60 条，避免全量渲染；
- **索引**：`notebook_uid`、`updated_at`、`deleted_at`、`status`、`note_tags.tag_uid`；
- **FTS 只索引标题与正文**，不索引附件与版本；
- **附件流式读取**：`http.ServeContent` 支持 Range，图片/PDF 不整块进内存；
- **导入/导出在请求内完成**，大文件受 64 MB 上传限制保护；
- **列表查询不返回正文**（`content` 为空），减少 JSON 体积；
- **前端虚拟化暂未实现**，以分页 + 按需加载替代（十万级列表建议后续加虚拟滚动）。

### 13.3 实测（本机，Apple Silicon）

| 操作 | 数据量 | 耗时 |
| --- | --- | --- |
| 列表首屏 | 15 篇 | < 20 ms |
| 标题搜索 | 15 篇 | < 10 ms |
| 目录导出 Markdown | 15 篇 | < 30 ms |
| 目录导出 XLSX | 15 篇 | < 50 ms |
| 备份（含附件） | 27 KB | < 100 ms |
| 恢复 | 27 KB | < 300 ms |

> 这是开发期的小样本数据，用于验证链路正确性；容量结论基于 SQLite 的公开特性与索引设计，而非压测结果。

## 15. 跨平台打包

### 15.1 macOS

- Go 交叉编译 `arm64` / `amd64`；
- 组装 `.app`（Info.plist + icns + 二进制），ad-hoc 签名；
- 生成 `.dmg`（含 Applications 快捷方式）；
- 数据目录固定为 `~/InkVault`，避免 `.app` 内部只读。
- 首次打开若被 Gatekeeper 拦截：右键 → 打开，或 `xattr -dr com.apple.quarantine`。

### 15.2 Windows

- 单文件 `.exe` + 启动 `.bat`；
- 数据在程序旁 `data/`，整个文件夹可复制；
- 控制台窗口保留，便于查看访问码与错误日志。

### 15.3 Android

- 不依赖 Gradle：`aapt2` 编译资源 → `javac` → `d8` → `zipalign` → `apksigner`；
- WebView 外壳，`file:///android_asset/www/index.html?local=1` 加载离线库；
- 也可连接电脑端（保存地址与 PIN，下次直接进入）；
- 导出通过 JS Bridge 写入系统「下载」目录。

### 15.4 iOS

- Xcode 工程（Swift + WKWebView），加载 Bundle 内 `www/`；
- 导出通过 `WKScriptMessageHandler` → 临时文件 → 系统分享面板；
- 未签名 IPA 可用 Sideloadly / AltStore 侧载；
- 正式分发需 Apple 开发者账号与签名。

## 16. 设计取舍与已知边界

| 取舍 | 选择 | 原因 | 代价 |
| --- | --- | --- | --- |
| 同步策略 | 全量 + LWW | 简单、可恢复、无需服务端状态 | 大量附件时慢；并发编辑会覆盖 |
| 版本历史 | 全文快照 | 恢复可靠 | 占用空间 |
| 标签 | 扁平 | 降低心智负担 | 不能原生树形 |
| 附件 | 文件系统 | 数据库轻量 | 备份需同时处理目录 |
| 移动端 | WebView + IndexedDB | 一套代码三端复用 | 性能不如原生；附件同步缺失 |
| 加密 | 不做应用层加密 | 避免密钥管理风险 | 依赖磁盘加密 |
| PDF | 浏览器打印 | 不引入重依赖 | 无服务端 PDF 生成 |

**明确的未实现项**：

- 实时协作 / CRDT；
- 端到端加密与单篇笔记加密；
- OCR / 图片文字识别；
- 双向链接图谱；
- 日历/看板视图；
- 插件市场；
- 移动端附件同步；
- 服务端全文索引的增量重建（当前为手动重建）。
